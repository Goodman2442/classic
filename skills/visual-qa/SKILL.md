# Визуальная проверка

Замыкающее звено дизайн-стека. Слои 01–04 генерируют, ревизуют и анимируют,
но ни один из них не смотрит на результат: агент правит вслепую по исходнику.
Этот скилл открывает глаза.

## Порядок

**1. Поднять страницу.** Статический файл снимается напрямую по пути.
Приложению нужен работающий дев-сервер — запустить его в фоне и дождаться порта.

**2. Снять.**

```
node ${CLAUDE_SKILL_DIR}/shot.mjs <url|путь.html> <папка-для-снимков>
```

По умолчанию снимается первый экран на 390, 834 и 1440 пикселях, в светлой и
тёмной теме — шесть кадров. Скрипт заодно ловит горизонтальный скролл на `body`
и ошибки в консоли: на снимке их не видно, а они ломают страницу.

Флаги: `--themes=dark` снять одну тему, `--full` добавить снимок всей страницы.
У длинного документа полный снимок выходит в десятки тысяч пикселей, детали на
нём не читаются — брать его только чтобы оценить ритм секций, не для критики.

**3. Посмотреть.** Открыть снимки инструментом чтения файлов. Это не
формальность: без этого шага скилл бессмысленен.

**4. Критиковать по списку.** Идти сверху вниз, называть конкретные места.

- Первый экран: заголовок влезает без обрезки, призыв к действию виден без скролла
- Тёмная тема: нет тёмного текста на тёмном фоне и наоборот, акцент работает на обоих фонах
- Типографика: строка не длиннее ~65 знаков, заголовки не рвутся по одному слову, нет висячих предлогов в заметных местах
- Сетка: элементы не налезают, отступы между однотипными блоками одинаковые
- Мобильная ширина: ничего не выпирает за экран, кнопки не переносятся в две строки
- Контраст текста и особенно кнопок не ниже AA
- Пустоты: нет ни слипшихся блоков, ни провалов в пол-экрана между секциями

**5. Починить и переснять.** Один проход правок, затем повторный снимок.

## Ограничение проходов

Максимум два цикла. Если после второго остаются замечания — выписать их
списком и отдать человеку, а не крутить дальше. Бесконечная полировка съедает
контекст и обычно делает хуже: правки начинают отменять друг друга.

## Стыковка со стеком

Этот скилл проверяет **то, что видно**. Он не заменяет `impeccable` — тот
судит по исходнику и ловит другое: иерархию, информационную архитектуру,
анти-паттерны. Разумный порядок для новой страницы:

```
design-taste-frontend → сборка → visual-qa → /impeccable:critique → visual-qa
```

Движение снимками не проверяется: статичный кадр ничего не скажет про кривые
и длительности. За это отвечает `review-animations`.

## Если Playwright не найден

```
npm i -g playwright && npx playwright install chromium
```

В облачных сессиях Claude Code Chromium уже стоит, ставить ничего не нужно.
